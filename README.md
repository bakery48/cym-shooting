# 回転砲塔 (cym-shooting)

同じ種類の弾でしか壊せない3種の敵を捌く、1ラン3分の縦シューティング。
ラン中に稼いだ金でその場で強化を買い、手作業を段階的に自動化していく。

- 企画書: [`docs/game-spec.md`](docs/game-spec.md)
- Steam販売までの計画: [`docs/steam-roadmap.md`](docs/steam-roadmap.md)
- 元のプロトタイプ（単一HTML・参考用）: [`prototype/turret-prototype.html`](prototype/turret-prototype.html)

## 動かす

ES モジュールを使っているため `file://` では開けない。静的サーバ経由で開く。

```sh
npm run dev            # http://localhost:8080 （依存なし・Node標準ライブラリのみ）
```

### スマホで遊ぶ（単一HTML）

全モジュールとCSSを1ファイルに畳んだものを吐き出せる。
サーバもインストールも要らないので、スマホに送ってそのまま開ける。

```sh
npm run build:single   # dist/cym-shooting.html （約50KB）
```

### スマホで遊ぶ（GitHub Pages）

リポジトリの `index.html` をそのまま配信すればよく、ビルドは不要。
パス指定はすべて相対なので、`/<リポジトリ名>/` 配下でも動く。

1. Settings → Pages → Source を **Deploy from a branch**
2. Branch に `claude/steam-sales-md-review-xpccam` と `/ (root)` を選んで Save
3. 1分ほどで `https://bakery48.github.io/cym-shooting/` が開く

push するたびに自動で更新される。公開リポジトリなのでURLを知っていれば誰でも見られる。

デスクトップ版（Steam向けのシェル）を動かす場合:

```sh
npm install
npm start              # Electron ウィンドウで起動
npm run dist           # release/ に配布用の展開済みディレクトリを出力
```

## 操作

| | |
|---|---|
| 移動 | ドラッグ（絶対座標追従）/ マウス追従 / <kbd>A</kbd><kbd>D</kbd> / <kbd>←</kbd><kbd>→</kbd> |
| 砲塔を回す（●→▲→■→●） | クリック / タップ / <kbd>Space</kbd> / <kbd>W</kbd> / <kbd>↑</kbd> |
| 強化を買う | クリック / <kbd>1</kbd>〜<kbd>6</kbd> |
| 中断 | <kbd>Esc</kbd> / <kbd>P</kbd> |
| 消音 | <kbd>M</kbd> |
| テスト用パネル | <kbd>`</kbd>（バッククォート） |

射撃は常時オート。プレイヤーは撃たない。

回転は**一方向のみ**。`●` から `■` は1タップ、`▲` は2タップ。この切り替え距離が
手数コストになり「今どの敵を処理するか」の判断を生む。3種を直接指定する入力を
足すとこのコストが消えるので、追加しないこと（企画書 §3）。

## レイアウト

縦持ち・横持ち・PCで同じコードが動く。盤面は**常に縦長のまま中央**に置き、
横に広い画面でも縦シューの見え方が変わらないようにしている。

| | 配置 |
|---|---|
| 縦持ち | 上からHUD → 盤面 → ショップ。ショップは親指の届く下端（企画書 §5） |
| 横持ち・PC | 盤面が中央、HUDとショップは右の縦カラム |

切り替えは幅ではなく**画面の向き**で行う。横持ちのスマホを幅で判定すると
縦積みのまま盤面が潰れるため。

## 敵

| | 見た目 | HP | 報酬 | 通る弾 |
|---|---|---|---|---|
| 白 | 白い菱形 ◆（やや小さい） | 1 | 5 | **どの弾でも** |
| 通常 | Y/C/M の塗り図形 ●▲■ | 1 | 12 | 種類が一致する弾のみ |
| 装甲付き | 同じ図形＋白い外枠＋HP数値 | 3 | 95 | **自機の弾のみ**（ポッドは弾かれる） |

白は装甲の外枠にも使っているが、意味は「**色＝弾種の要求**」で一貫している。
装甲敵の塗りはY/C/Mのままで白は枠にすぎず、白い敵は塗りそのものが白い。
**色が無い＝要求が無い。** 形も ●▲■ と別にして読み違えを防いでいる。

白い敵も突破すれば1カウント。報酬は安いが見逃せない、という位置づけで、
自動化に価値を持たせる役割を持つ。ポッドは自分の種類を優先し、
居ないときだけ白を撃つ。

## 面とモード

内容量はステージ制で作る。前の区をクリアすると次が開く。

強化は二層。**ラン内強化はコインで買い、毎ランリセットされる**ので、
「全手動 → 部分自動 → 手が装甲へ」の弧が毎ラン成立する。
**恒久強化はコアで買い、ランをまたいで残る**。

| | 通貨 | 買う場所 | ランをまたぐか |
|---|---|---|---|
| ポッド3種・連射・貫通・拡散 | コイン | ラン中のショップ | 戻る |
| 僚機・防壁・弾芯 | コア | 面選択画面 | 残る |

コアはクリアで +3（初クリアはさらに +5）、失敗でも +1。
**恒久側に置けるのは1ラン内の弧に触れない強化だけ** ― ポッドを恒久にすると
2周目が「最初から自動化済み」で始まり、コアループが死ぬ。
僚機が白い ◆ しか撃たないのはそのため。

| | 尺 | 性格 |
|---|---|---|
| 第1区 展開 | 3:00 | 3種が均等。全手動から自動化までの基本の弧 |
| 第2区 圧 | 3:00 | 数と落下が速い。自動化を踏む判断が早くなる |
| 第3区 偏り | 3:00 | ■ に大きく偏り、買うポッドの順番が成否になる |
| 第4区 装甲 | 3:00 | 装甲付きが多く、手はほぼ装甲専任になる |
| 第5区 密集 | 2:00 | 短いかわりに最初から量が多い。所持金150で開始 |
| 第6区 完走 | 5:00 | 終盤はポッドだけでは追いつかず手が戻ってくる |
| 手動限定 | 3:00 | ポッドを買えない。企画書 §10 の仮説1の検証を兼ねる |
| 全自動 | 3:00 | ポッド3基を最初から持ち、装甲付きしか金にならない |

保存するのは開放状況と自己ベストだけ。`js/core/save.js` を参照。

## 設計上の約束

企画書から動かしてはいけないもの:

1. **画像アセットを使わない。** 円・三角・矩形・線・粒子だけで成立させる。
   音も同じで、音源ファイルを持たず Web Audio API で合成する
2. **強化は必ず画面上の変化として現れる。** 数値だけ増える強化は追加しない
3. **色は装飾ではなく情報。** ●▲■ の3色は弾種と敵種の対応そのもので、他に流用しない
4. **チューニング値は `js/config.js` に集約する**

## テストプレイ用の調整

面選択画面で <kbd>`</kbd>（バッククォート）を押すと調整パネルが開く。
`?dev` を付けたURLでも開く。開閉状態は保存される。

- **コア** ― 直接入力、または ±10
- **恒久強化のレベル** ― 各項目を ± で直接上下できる。
  コアを増やすだけでは買う方向にしか動けず、いったん買った強化を外して
  試すのに記録の全消しが要るため
- **区** ― すべて開放 / 開放を戻す

`js/dev.js` にまとまっていて、ゲーム側のロジックからは参照していない。
出荷時は `js/main.js` の `createDev` の2行を外せば消える。

実行中は `window.__G`（ラン状態）・`window.__CONFIG`・`window.__PROGRESS` が
コンソールからも見える。こちらも覗き窓で、ゲーム側からは参照していない。
