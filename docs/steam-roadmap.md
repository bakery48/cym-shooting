# Steam販売までの計画

作成: 2026-09-05
対象: `docs/game-spec.md` の企画をSteamで売れる形にするまで

この文書は「何が足りないか」を正直に並べるためのもの。
実装の指針ではなく、判断が必要な項目の一覧として使う。

---

## 0. 最初に直視すべきこと

企画書の設計は**スマートフォンのブラウザで3分遊ぶ**ことを前提に組まれている。
Steamは有料PCゲームの店で、購入者は数時間ぶんの内容量を期待する。
つまりSteam化とは移植作業ではなく、**遊べる総量を作る作業**になる。

現状で不足しているのは技術ではなく分量:

| | 現状 | 有料Steamタイトルの実質的な下限 |
|---|---|---|
| プレイ時間 | 1ラン3分・モード1つ | 2〜5時間ぶんの目的 |
| 繰り返す理由 | なし（ラン間の永続進行はスコープ外） | 実績・記録更新・アンロック等 |
| 見た目 | 図形のみ・アセットなし | ストア画像とトレーラーは必須 |
| 音 | なし | 最低限のSE。無音は返金理由になる |

技術面（デスクトップ操作・ウィンドウ・パッケージング）は済んでいる。
残りはすべて**内容量と体裁**の作業になる。

## 2. 内容量（最大の作業。ここが未決定）

企画書 §10 フェーズ3で「意図的に決めていない」とされている項目が、
そのままSteam化の可否を決める。**実装前に判断が要る。**

### 2-1. ラン間の永続進行を入れるか

現状スコープ外。しかし入れない場合、3分遊んで終わりのものを有料で売ることになる。
選択肢:

- **A. 永続進行を入れる** ― アンロック式の強化・新しいポッド種・開始時ボーナス。
  最も素直に「続ける理由」を作れるが、企画書 §6 の原則（強化は画面上の物として出す）を
  メタ進行にも適用する必要がある。数値だけ伸びるツリーにすると設計が崩れる。
- **B. 進行なしのまま、ステージ制やモードで量を作る** ― 敵の構成が違う面を並べる。
  1ラン3分の緊張感は保てるが、面ごとの設計コストが高い。
- **C. スコアアタック特化** ― 実績とリーダーボードだけで反復理由を作る。
  作業量は最小だが、この方向は競争が激しく、売れる可能性は最も低い。

### 2-2. 尺（現在180秒）

1〜5分の想定内で調整可能とされている。永続進行を入れるなら短め、
1ランで完結させるなら長めが噛み合う。2-1 とセットで決める。

### 2-3. 複合敵（複数の弾種を要求する敵）

出すなら中盤以降の変化として効く。出さないなら3分の弧を別の手段で作る必要がある。

## 3. 体裁（内容が決まってから着手）

### 音
未着手。Web Audio API で合成する想定（音源ファイルは使わない方針）。
撃破・弾かれ・購入・突破の4つだけでも体感は大きく変わる。
**無音のまま出さないこと。**

### ストア用画像
ゲーム本体は画像アセットを使わない方針だが、**ストアページは別**で、
規定サイズの画像を出さないと審査を通らない。
図形と3色のパレットをそのまま使えば、絵が描けなくても成立させられる。

必要なもの（サイズは Steamworks の最新ドキュメントで必ず確認すること。変更される）:
- ヘッダーカプセル / メインカプセル / 縦型カプセル
- ライブラリ用画像（ライブラリ表示・ヒーロー画像・ロゴ）
- スクリーンショット複数枚
- トレーラー動画（実質必須。ゲーム画面の録画で足りる）

### ローカライズ
UIの文字数は少ない。日本語と英語の2言語は費用対効果が高い。
現在は文字列がHTMLとJSに直書きなので、切り出す作業が要る。

## 4. Steamworks 側の作業

順序に依存関係があるので早めに着手する。金銭と本人確認が絡む部分は時間がかかる。

1. **Steamworks への登録と Steam Direct の手数料支払い**
   （1アプリごとの手数料。一定の売上に達すると返金される仕組み。金額と条件は公式で確認）
2. **銀行口座・税務情報の登録** ― 本人確認が要るため最も待たされる。最初にやる
3. **ストアページの作成と審査**
4. **「近日登場」ページの公開** ― Steamは発売日より前に一定期間ストアページを
   公開しておくことを求めている。期間は公式の要件を確認し、逆算して計画する
5. **ビルドのアップロード（depot）** ― `npm run dist` の出力をそのまま上げる
6. **年齢レーティング / コンテンツ申告**
7. **リリース**

### 実績・リーダーボード（任意）
Steamworks SDK との連携が要る。Electron から使う場合はネイティブモジュールが必要で、
`steamworks.js` などの選択肢がある。導入する場合はビルドがプラットフォームごとに
分かれるので、内容（2-1）が固まってから判断する。

## 6. 進める順序（提案）

内容量の判断（§2）が全体の前提になるので、そこから始める。

1. **§2-1 を決める** ← 今ここ。これが決まらないと以降が全部変わる
2. フェーズ2の仮説検証（既存の3分ループが本当に面白いかの確認）
3. 音の実装（最も費用対効果が高い）
4. 決めた方向での内容量の実装
5. 設定・保存・ゲームパッド
6. ストア用画像とトレーラー
7. Steamworks 登録（税務情報だけは §1 と並行して先に着手してよい）
