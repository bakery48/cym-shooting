# 回転砲塔（仮題）― 企画書

作成: 2026-09-05 / 想定実装者: Claude Code
先行プロトタイプ: `turret-prototype.html`（単一HTML、動作確認済み）

---

## 1. 何を作るか

上から降りてくる3種の敵を、**同じ種類の弾でしか壊せない**縦シューティング。
1ラン3分。ラン中に稼いだ金でその場で強化を買い、手動でやっていた仕事を段階的に自動化していく。

一言で言うと「マッチング作業のインクリメンタル化」。作業の正解が3択しかないので思考負荷は低く、代わりに**手数と時間の配分**がプレイの中身になる。

### 設計上の制約（意図的）

- **画像アセットを一切使わない。** 円・三角・矩形・線・粒子のみで成立させる。作者が絵を描けなくても作れることが企画の前提。
- **強化は二層に分ける。** ~~メタ進行（ラン間の永続強化）は初期スコープに含めない。~~
  → **変更（2026-09-05）: ラン内強化と恒久強化の二層構成にする。**
  - **ラン内強化**（コイン・毎ランリセット）― 既存の6種すべて。
    コインも毎ランゼロから。これで §2 の弧が**毎ラン成立する**
  - **恒久強化**（コア・面選択画面で買う）― ランをまたいで残る唯一の強さ。
    **1ラン内の弧に触れる強化はここに置かない**（ポッドを恒久にすると
    2周目が「最初から自動化済み」で始まり、コアループが死ぬ）
- **強化の効果は必ず画面上の変化として現れる。** 数値だけが増える強化は作らない。ここが最重要の設計原則（§6参照）。

## 2. コアループ

```
敵が降りてくる
  → 弾種を合わせて撃つ（手動）
  → 金が入る
  → ポッド（自動砲台）を買う
  → その種類は手が空く
  → 空いた手を装甲敵に回す
  → 装甲敵は単価が高いので金が加速
  → さらに強化 …
```

3分で「全部手動 → 3種すべて自動 → 手は装甲敵専任」まで到達するのが基本の弧。
終盤は落下速度が上がってポッドだけでは処理が追いつかなくなるので、**手が通常敵の処理にも部分的に戻ってくる**。ここが「自動化したのに暇にならない」を担保する仕組み。

## 3. 操作

| 入力 | 動作 |
|---|---|
| 画面上を横にドラッグ | 自機が横移動（絶対座標追従） |
| 画面を軽くタップ（移動量 < 10px） | 砲塔が一段回転 → 弾種が `●→▲→■→●` の順に切り替わる |
| （射撃） | 常時オート。プレイヤーは撃たない |

タップとドラッグは移動量の閾値で判別する。単一ポインタのみ対応でよい。

**回転が一方向なのは意図的な設計。** `●` から `■` へは1タップ、`▲` へは2タップかかる。この「切り替え距離」が手数コストになり、どの敵を今処理するかの判断が生まれる。**3種を直接指定するボタンにしてはいけない**（コストが消えて単なる色合わせになる）。

## 4. ゲーム要素

### 敵

| 状態 | インク | 必要弾数 | 撃破報酬 |
|---|---|---|---|
| 白（素地） | なし | 1（どの色でも） | 5 |
| シアン / マゼンタ / イエロー | 1本 | 1 | 12 |
| 青 / 緑 / 赤 | 2本 | 2 | 24 |
| 黒 | 3本 | 3 | 36 |

**敵はインクを重ねた状態として持つ（減法混色）。** 同じ色で撃つとその色が剥がれ、
全部剥がれると落ちる。赤は M+Y、緑は C+Y、青は C+M、黒は三色すべて。

```js
enemy.inks &= ~bullet.ink;      // C=1, M=2, Y=4
if (enemy.inks === 0) 撃破
```

- **剥がす順番は問わない。** 赤にMを当てれば黄、Yを当てればマゼンタになる。
  プレイヤーは回転距離の近いほうを選べる
- 難度は色の構造からそのまま出る ― 単色は回転0回、2色は1回、黒は2回
- 報酬は**元々乗っていた**インクの本数で決まる（撃破時の残りで数えると必ず取りこぼす）
- **装甲付き**はインクとは別の軸。ポッドの弾を弾き、自機の弾でのみ壊れる。報酬は4倍
- 白（素地）は剥がすものが無いので一発で割れる。装甲とは排他
- 乗っていない色の弾は弾かれる。**【未決定】** 減法混色なら「インクが増える」ほうが
  自然という案があり、これは課題として残している（`docs/next-design.md`）

#### 混色は時間をかけて増やす

混色を最初から全種類降らせると、**色を分解する作業に頭が追いつかなくなる**
（実プレイで確認済み）。企画書 §1 は「思考負荷は低く」を掲げているので、
ここは緩める側に倒す。

- **序盤は混色なし → 1種 → 2種 → 3種 → 最終盤に黒**、の順に開く
- 各構成は `from`（ラン全体に対する登場時刻）を持つ。重みを `[登場時, 終了時]` と
  書けば「たまに → 普通」も表せる（黒はこれで最終盤に増える）
- **登場したばかりの混色はゆっくり落ちる**（単色の 0.55倍）。慣れる頃には
  単色と同じ速さに戻る。解読の時間が要るのは覚えたての色だけ
- **何が混ざっているかを、混ざる前の色の点で敵の上に示す。**
  色と模様だけだと「赤 = マゼンタ＋イエロー」を頭の中で分解する必要があり、
  複数体が同時に降ると追いつかない。素の色を並べれば分解が要らない。
  単色と素地には出さない（分解するものが無く、点は邪魔になる）

注意: **遅く落とすと画面上の同時数は増える**（滞空時間が伸びるため）。
負荷の実体は「体数」ではなく「**同時に降っている混色の種類数**」なので、
そちらを 0 → 1 → 2 → 3 → 4 と増やす形で抑えている。

#### だんだん賑やかになる（密度カーブ）

**1ランのあいだに in と out の両方が増え続ける**こと。これが手応えの本体で、
混色の段階解放（上）と並ぶ、ラン内の時間設計のもう一本の柱。

| | 何が増えるか | どう増やすか |
|---|---|---|
| in | 降ってくる敵の数 | `spawn` の密度カーブ（毎秒の湧き数を rate0 → rate1 へ） |
| out | 撃破数・発射数・破片 | ショップで手数が増える。**尽きないこと**が条件 |

- **毎秒の湧き数で補間する。** 間隔（秒）を等速で詰めると、毎秒の数は
  終盤だけ跳ね上がる形になり、中盤がずっと平坦なまま最後だけ洪水になる。
  毎秒の数で補間すれば画面の濃さがそのまま素直に増える
- `curve > 1` で後半ほど伸びる。序盤を薄くしておくのは、
  「増えた」と感じるには先に薄い時間が要るため
- **out が伸びない面では in も伸ばさない。** ポッドを買えない `m1` の
  カーブがいちばん浅いのはそのため（in だけ伸ばすと、ただ理不尽になる）
- 盤面に**居る**敵の数は防衛ラインが上限を作るので、無限には増えない。
  増えるのは流量（湧き・撃破・発射）で、画面上はそれが弾と破片と
  ポッドの輪として出る

### 役割

照合の負荷ではなく「**どこにいるか・いつ撃つか**」を問うための軸（企画書 §1）。
面ごとに重みで出現比を決め、全部いっぺんに降ってこないようにする。

| 役割 | 内容 | 生む判断 |
|---|---|---|
| `normal` | ふつう | ― |
| `split` | 撃破すると素地の小さい敵2体が左下・右下へ加速しながら開く | **倒す高さ**。高いうちに割れば破片を処理する時間ができる |
| `cluster` | 同じ単色が3〜5体まとまって湧く | **立ち位置**。1体ずつ追うと間に合わない |
| `dive` | ゆっくり落ちてきて、途中で止まってから急加速する | **いつ撃つか**。遅いうちに片づけるか、他を優先して後で慌てるか |
| `carry` | 報酬2.5倍。突破されると突破が2進む | **優先順位**。他を捨ててでもこれを落とすか |
| `breed` | 落下は0.45倍と遅いが、3.4秒ごとに倍々に分かれる（8体まで） | **処理の順番**。後回しにできない一体を作る |

制約:
- **群れは必ず同じ単色**にする。混色を並べると照合の負荷が跳ね上がり、
  この役割の狙い（位置取りだけを問う）が壊れる。装甲も分裂も混ぜない
- **分裂は黒（3発）と重ねない。** 3発かけたうえに破片2体は重すぎる
- 破片は素地なのでどの色でも落とせる（照合の負荷を足さない）。再分裂もしない
- 破片は重なった位置から左下・右下へ**加速しながら**開く（`motion: 'burst'`）。
  等速で分かれるより「割れた」に見えるのと、開き方が時間とともに変わるので
  親を撃った位置のまま構えていると両方とも取り逃す。
  「割った後に動き直す」ことが判断の実体
- 壁では**跳ね返る**。勢いを殺すと、斜めに飛んだものが急に真下へ落ち始めて
  見えて違和感が出る。弾けた勢いは一度きりなので、跳ねた後は加速をやめ、
  反発ぶん（0.8倍）だけ弱まった速度で戻る ― 壁の間を等速で往復し続けない
- **急降下は加速の前に必ず予備動作を出す**（0.55秒その場で止まり、輪が広がる）。
  予告なく速くなる敵は理不尽にしかならないので、ここは省略できない
- 急降下の落ち方は `drift` 固定。揺れながら急降下されると挙動が読めない
- **運び屋は素地と重ねない。** 安い敵に重い突破ペナルティが付くと読み違えのもとになる。
  代わりに半径1.15倍・落下0.85倍で「大きくて重い」ことを見た目と挙動で示す
- 防壁（恒久強化）は突破1件を**丸ごと**受け止める。運び屋の重い突破ほど守れるほうが、
  防壁を残しておく判断に意味が出る
- **増殖は必ず単色・非装甲。** 倍々に増えるものの照合が重いと詰みに直結する
- **増殖の報酬は世代ごとに半分。** 早く潰しても、増やしきってから全部倒しても
  総額は同じ（元が通常の2倍）。稼ぐために泳がせるのが最適解になると、
  この役割の狙い（後回しにできない）が壊れる
- **増殖までの残り時間を弧で表示する。** いつ増えるかが読めないと、
  後回しにした結果が運になる
- **分かれるときは左右へ加速して離れる。** その場で倍になるだけだと重なったまま
  並ぶので、1発の射線でまとめて落ちて「増えた」ことの意味が消える
- 押し幅は世代が進むほど狭める（`kick.genScale`）。等幅で押すと
  「左へ出た子」と「右へ出た子」が同じ位置で出会って重なる（-d+d = +d-d）。
  加えて分裂の間隔と押し幅を個体ごとにばらして、格子状に並ばないようにしている

### 形と挙動

**形は役割、色はインク。** 2つのチャネルがそれぞれ1つずつ意味を持つ
（**形で弾の種類を区別することはしない** ― どの色で撃つかは色だけが決める）。

| 役割 | 形 | 読ませ方 |
|---|---|---|
| `normal` | 六角形 | 基準 |
| `cluster` | 正方形 | 並ぶと壁に見える |
| `split` | ひょうたん | くびれが「2つに割れる」ことを示す |
| `dive` | 下向きの楔 | 回転させないので、尖った先が常に落下方向を指す |
| `carry` | 八角形＋内枠 | 大きく重い。内枠は塗りの明るさで色を反転させる（黒でも消えない） |
| `breed` | とげ玉 | 他は全部なめらかな凸多角形なので、遠目でもここだけ浮く。外周の弧が増殖までの残り時間 |

自機は三角、ポッドは円、僚機は菱形なので、敵とは形で区別できる。

落ち方は色と役割に対して直交する軸。


| 落ち方 | 内容 |
|---|---|
| `drift` | まっすぐ落ちる |
| `leaf` | 木の葉のように左右に揺れながら、少し遅く落ちる |
| `dodge` | 遅い代わりに、自機と同じ縦軸から常にずれ続ける |
| `burst` | 分裂の破片。左下・右下へ加速しながら開く（面の指定には出さない） |

`dodge` が**弾ではなく自機の位置**を見るのは、弾に反応させると
「撃った瞬間に逃げる」ので当たらない理由がプレイヤーから見えないため
（撃つ → 外れる、の繰り返しにしかならない）。自機の位置だけを見て
じりじりずれるなら、**自分がどこに立っているか**が理由になり、
追い込む・回り込むという手が意味を持つ。ずれ終わったら止まり、
画面端に詰まったら向きを変えて自機の上を横切る（端に張り付かせない）。

ポッドも真上にしか撃たないので、この敵はポッドの弾幕からも自然に外れる。

#### 形をなくしたぶんを模様で補う

形を統一すると色だけが情報チャネルになり、色覚特性のあるプレイヤーが遊べなくなる
（赤と緑の区別は最も頻度が高い）。**塗りに模様を重ねて冗長性を戻す。**

| インク | 模様 |
|---|---|
| C | 横線 |
| M | 縦線 |
| Y | 点 |

混色は模様が重なるので、**何色が乗っているかが模様からも読める** ―
色覚への配慮であると同時に、混色そのものの可読性にも効いている。
模様の色は塗りの明るさで反転させる（明るい塗りの上では白い模様が消えるため）。

黒は背景（`#232a45`）とのコントラストが 1.20 しかないので、縁を描いて浮かせる。
- 敵が防衛ライン（画面下端付近の破線）を越えると「突破」1カウント。**10回で即終了**

### 自機

画面下部、水平方向のみ移動。上向きに一定間隔で自動発射。
自機の周囲に3連バレルのリングを描画し、現在の弾種を最上部に拡大表示する。回転はイージングでアニメーションさせる（切り替えの手応えの大部分がこの動きにある）。

### ポッド（自動砲台）

購入すると自機の**周囲を公転する**小さな球体として出現する。
- **弾は真上にしか飛ばない。狙わない。** 狙って撃たせると「どこに立つか」の
  判断がまるごとポッドに肩代わりされ、公転させている意味も消える。
  真上固定なら、公転で左右に振れるポッドの下に敵を入れる＝**自機の位置取り**が
  そのままポッドの当たり外れになる
- **的の有無にかかわらず一定間隔で撃ち続ける。** 撃ち止めると弾幕が途切れて
  「その下に敵を入れる」対象が消えるうえ、撃つ撃たないの理由が画面から読めない。
  外れ弾はコストではなく、公転する弾幕そのものが盤面の情報になる
- 装甲敵は弾を弾く。真上にいても止めないので、当たって弾かれる
- 発射間隔は自機の1.4倍。撃ち続けるぶん、自機よりは遅くしてある
- 公転させているのは、購入するほど自機周りが賑やかになるのと、自機の移動がポッドの射線に直結して意味を持つため。画面端の固定砲台にはしない
- **公転の航跡を帯として描く。** 点が回っているだけだと「賑やかになる」が弱いので、
  各ポッドが自分の色の弧を曳く。3基そろうとほぼ輪になり、自動化の度合いが一目で分かる。
  航跡は自機からの相対座標で持つ（絶対座標だと、マウス追従で自機が瞬間移動したときに
  直線の尾が伸びてしまう）。加算合成は使わない ― 3色が重なって白くなると、
  白が持つ「弾種を持たない」の意味と衝突するため（§7）
- **同じ色を何基でも増設できる（上限なし）。** 1基目が自動化の開始で、
  2基目以降は終盤の金の行き先。上限を作ると、そこで out の伸びが止まって
  画面が寂しくなり、余った金が死ぬ
- 増設ぶんは公転位相が散るので、覆う列が自然に分かれる
- 基数が増えるほど公転の輪を**横に**広げる。縦は広げない ―
  下に伸びると輪が防衛ラインを跨いで意味が濁る

## 5. 強化（ラン中購入）

画面下部の横スクロールバーに常時表示。買える時だけ枠が光る。

| ID | 名称 | 効果 | 価格 | 上限 |
|---|---|---|---|---|
| `podM` | マゼンタ ポッド | M を剥がす自動砲台を1基追加 | 140 ×2.2^n | なし |
| `podC` | シアン ポッド | 同上（C） | 210 ×2.2^n | なし |
| `podY` | イエロー ポッド | 同上（Y） | 300 ×2.2^n | なし |
| `rate` | 連射速度 | 発射間隔 -0.07秒（自機・ポッド両方） | 130 ×1.65^n | 5 |

**ラン内で伸びるのはポッドと連射だけ。** 貫通弾は外した（弾が強すぎて、
位置取りも色合わせも要らなくなる）。拡散弾は恒久側へ移した（下）。
残ったぶん、ラン内の弧は「自動化をどこまで積むか」に一本化されている。

ポッド3種の1基目の価格が段階的に上がっているのは、購入順に自由度を持たせつつ
「最初の自動化をいつ踏むか」を意思決定にするため。

**ポッドだけ上限を置いていない。** 他が全部埋まったあとも金の行き先が残るので、
終盤に out（撃つ手数）が伸び続け、稼いだ金が死なない。倍率 2.2 が実質の歯止めで、
増設するほど1基あたりの価格が跳ね上がる。

### 恒久強化（ラン外購入・コア）

面選択画面で買う。ランをまたいで残る唯一の強さ。

| ID | 名称 | 効果 | 価格（コア） | 上限 |
|---|---|---|---|---|
| `wing` | 僚機 | 白い ◆ だけを狙う小型機が自機の脇に付く | 8 / 20 | 2 |
| `shield` | 防壁 | 防衛ライン上の障壁が突破を肩代わり。ランごとに戻る | 6 / 14 / 26 | 3 |
| `core` | 弾芯 | 自機の弾が太くなる | 5 / 12 / 24 | 3 |
| `fire` | 速射 | 自機の発射間隔が1段ごとに13%短くなる。**ポッドには乗らない** | 7 / 16 / 34 / 70 | 4 |
| `spread` | 拡散弾 | 自機の発射数 +1（扇状）。ポッドと僚機には乗らない | 10 / 24 / 48 | 3 |

**ここに置けるのは1ラン内の弧に触れない強化だけ。**
**ポッド**を恒久側に出すと、2周目以降が「最初から自動化済み」で始まり、
§2 のコアループが成立しなくなる。触れてはいけないのはそこ。
僚機が白い ◆ しか撃たないのはそのため ― 弾種を持つ敵には手を出さない。

拡散弾と速射がここにあるのは、どちらも「手で撃つ側」を太くする強化で、
自動化の弧そのものには触れないため。恒久で強くなるのは手動フェーズの底上げで
あって、ポッドを買う動機は減らない。

**速射がポッドに乗らないのはこの原則から。** ラン中の「連射速度」は自機と
ポッドの両方を速くするが、恒久側で同じことをすると、2周目以降は自動化そのものが
最初から底上げされた状態で始まってしまう。恒久で速くなるのは自機だけにしてある。

**そのぶん、面の難度は恒久強化の前提つきで決めている。**

| 面 | 前提 |
|---|---|
| 1-1 / 1-2 | 恒久0（買う前） |
| 1-3 | **拡散Lv1**（1-1・1-2 のクリアで入る16コアで買える） |
| 2-1 〜 2-3 | 各1段（僚機/防壁/弾芯/速射/拡散を1つずつ ＝ 36コア） |
| 手動限定 / 全自動 | それ以上 |

1-3 に拡散を要求しているのは、ここが「恒久強化を1つ買う」を体験させる位置だから。
自動プレイでの完走率は、拡散なしで 8/10、拡散Lv1 で 10/10。

§6 の原則は恒久側にも同じく適用する。上の3つはそれぞれ
「脇に付く小型機」「ラインに立つ障壁」「太くなる弾」として画面に出る。

## 6. 最重要の設計原則

> **強化は「自分の仕事が減る」ではなく「画面上の物が増える」として見せる。**

引き算型の強化（自動化・楽になる系）は、効果が「消えたもの」なので体感が立たない。プロトタイプの前身（仕分けゲーム版）はここで失敗した。

したがって:
- 自動化は **公転するポッドという物体** として画面に出す
- 火力強化は **弾数・弾の太さ・ポッドの基数** として画面に出す
- 単価倍率、ミス許容数増加、クールダウン短縮のような**画面が変わらない強化は追加しない**

新しい強化を足す時は必ず「これは画面上で何が増えるか」を先に答える。答えられない強化は採用しない。

## 8. 技術

- 単一HTMLファイル、依存ライブラリなし、Canvas 2D、ビルド不要
- 描画は DPR 対応（`devicePixelRatio` は 2 で上限）
- 速度系の数値は画面高 640px を基準にスケール（`S = H / 640`）して、端末が変わっても体感を揃える
- 入力は Pointer Events に統一。マウスとタッチで同じコードパス
- `dt` は最大 0.05 秒でクランプ（タブ復帰時の飛びを防ぐ）
- HUD（時間・所持金・突破ゲージ・ショップ）は DOM、ゲーム本体は Canvas
- 全チューニング値をファイル冒頭の `CONFIG` オブジェクトに集約する。**ロジック中に数値をベタ書きしない**

### 現行の CONFIG

```js
const CONFIG = {
  runSeconds: 180,
  maxBreach: 10,
  kill: { perInk: 15, armoredMul: 4, bare: 5 },
  armoredChance: { base: 0.05, perSec: 0.0004 },
  // 毎秒の湧き数を rate0 -> rate1 へ、進行度の curve 乗で増やす
  spawn: { rate0: 0.55, rate1: 6.0, curve: 2.0 },
  fall:  { start: 46,   rampPerSec: 0.55 },
  ship:  { fireBase: 0.60, fireMin: 0.20, firePerLv: 0.07, bulletSpeed: 560 },
  pod:   { orbitRadius: 58, orbitSpeed: 0.9, fireMul: 1.15, bulletSpeed: 460, range: 520,
           ringPerPod: 0.07, ringMax: 1.75 },
  tapThreshold: 10,
  costs: {
    pod: { C: 210, M: 140, Y: 300 }, podMul: 1.9,
    rate:   { base: 130, mul: 1.65, max: 5 },
  },
};
```


## 10. 作業の進め方

### フェーズ1: プロトタイプの整理
`turret-prototype.html` は動作するが、探索的に書かれている。まず以下を整理する。

- [ ] 描画・更新・入力・ショップをモジュールに分割（単一ファイル維持は可）
- [ ] 自機の3連バレル描画に未使用変数と冗長な条件式が残っているので整理
- [ ] `syncPods()` の初期化ロジックを整理（`p.a === undefined` の後追い代入をなくす）
- [ ] リサイズ時に進行中のランが壊れないことを確認

### フェーズ2: 検証したい仮説
プロトタイプで確かめきれていないのはこの2点。実装より先に、この2つを測れる状態にする。

1. **タップ回転のコストが緊張として機能しているか。** 機能していなければ、逆回転（上下フリック）を足すか、切り替えにクールダウンを設けて別の形でコストを残す。3種直接指定にする案は最後の手段
2. **拡散が「強くなった」として体感できているか。** 弾の見た目の変化が足りなければ、発射時の反動演出を足す

### フェーズ3: 未決定の項目
以下は意図的に決めていない。実装時に判断が必要になったら**先に確認を取ること**。

- **次に入れる要素の構想と、実装前に決めることは
  [`docs/next-design.md`](next-design.md) にまとめてある**
  （混色の敵 / 弾種の段階解放 / 形の統一と挙動による差別化）
- ~~ラン間の永続進行を入れるか（現状スコープ外）~~
  → **決定: 二層にする。** 一度「所持金と強化をすべて永続」にしたが、
  実プレイで §2 の弧が2周目から消えることが確認できたため、
  **ラン内（コイン）と恒久（コア）を分離**した。

  | | 通貨 | 買う場所 | ランをまたぐか |
  |---|---|---|---|
  | ラン内強化（ポッド3色・連射） | コイン | ラン中のショップ | **戻る** |
  | 恒久強化（僚機・防壁・弾芯） | コア | 面選択画面 | **残る** |

  コアは**ラン終了時にだけ**入る。クリアで +3、初クリアはさらに +5、失敗でも +1。
  獲得の瞬間も条件も見えないという指摘があったため、
  走行中のHUDに「クリアで コア +N」を予告し、リザルトでは統計に混ぜず
  単独の枠で「獲得数 → 所持数」を出している。
  記録は面選択画面からいつでも消せる。
- 複数の弾種を要求する複合敵を出すか
- 3分という尺が適切か（1〜5分の想定内で調整の余地あり）
- BGM・効果音（未着手。効果音は Web Audio API で合成する想定、音源ファイルは使わない）
